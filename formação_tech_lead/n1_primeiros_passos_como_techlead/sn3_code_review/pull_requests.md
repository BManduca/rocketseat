# Pull Request
- Muitas vezes nos deparamos com PRs sem descrição, o que acaba gerando confusão e problemas na revisão de código.
- Para um bom PR:
  - acima de tudo e necessário ter transparência
  - Buscar explicar sempre o que você fez, como você fez, como deve ser testado.
  - Facilitar a revisão de código, reduzindo muito os maus entendidos e reduz muito o problema das pessoas não entenderem exatamente aquela feature.
- Como Tech Lead, temos que buscar ser facilitador dessas 'coisas', que a gente dê esse exemplo , que possamos chegar no projeto e consiga ajudar o time, criando esses padrões e fazendo com que esses mesmos sejam seguidos.
- Objetivo principal ao criar o padrão:
  - Tornar fácil a leitura e fácil o acesso, reduzindo assim, a repetição que teríamos, caso a gente criasse tudo na mão.

- Aspectos mais importantes para um bom template de Pull Request:
  - Descrição e Título claro
